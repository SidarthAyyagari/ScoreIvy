# Deploying ScoreIvy

How the site goes from this repo to `scoreivy.com`, and how changes ship afterwards.

| Piece | Render service | Address |
| --- | --- | --- |
| Student site (`ui_user`) | `scoreivy-web` | `scoreivy.com` (and `www`) |
| Admin site (`ui_admin`) | `scoreivy-admin` | `admin.scoreivy.com` |
| Backend (`backend`, Docker) | `scoreivy-api` | `api.scoreivy.com` |
| Postgres | `scoreivy-db` | private to Render |

Everything is defined in [`render.yaml`](render.yaml). The automated checks are in [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

## How a change ships

1. Work on a branch, push it, and open a pull request.
2. GitHub Actions runs the checks: backend tests, production builds of both sites, and the backend Docker image.
3. Merge only when all checks are green (enforced by branch protection, step 1 below).
4. Render deploys `main` automatically once the checks pass. Database migrations run when the backend starts.
5. If a deploy goes wrong: Render dashboard → the service → **Events** → roll back to the previous deploy.

## One-time setup

### 1. Automated checks (GitHub)

The workflow runs on every pull request and every push to `main`. After it has run once:

GitHub repo → **Settings → Branches → Add branch protection rule** for `main`:
- Require a pull request before merging.
- Require status checks to pass: `Backend tests`, `Build ui_user`, `Build ui_admin`, `Backend image builds`.

### 2. Accounts you need

- **Render** ([render.com](https://render.com)), signed in with GitHub and given access to this repo.
- **Google Cloud**: the OAuth client you already use locally.
- **Stripe**: an account. Test mode is enough for the first deploy.
- **Domain registrar** for `scoreivy.com`: your mom's login (GoDaddy, Namecheap, Google/Squarespace, ...), or she adds the DNS records for you. Nothing else is needed from her.

### 3. Create everything on Render

Render → **New → Blueprint** → pick this repo. Render reads `render.yaml` and asks for the values that aren't committed:

| Setting | Where it goes | Value |
| --- | --- | --- |
| `GOOGLE_CLIENT_ID` | api | Your Google OAuth client ID |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | web, admin | The same client ID |
| `ADMIN_EMAILS` | api | Comma-separated Google emails of admins (you, your mom, the experts) |
| `STRIPE_SECRET_KEY` | api | `sk_test_...` at first; `sk_live_...` at launch |
| `STRIPE_WEBHOOK_SECRET` | api | From step 6 (put any placeholder until then, then update) |
| `NEXT_PUBLIC_DESMOS_API_KEY` | web | Optional, enables the SAT graphing calculator |

`SECRET_KEY` is generated by Render. The database connection is wired up automatically. Sample data is never loaded in production.

The backend refuses to start in production if a required setting is missing or unsafe; the error is in the service's **Logs**.

Note: `NEXT_PUBLIC_*` values are baked into the sites when they build. After changing one, redeploy that site.

### 4. Domain (DNS)

In Render, open each service → **Settings → Custom Domains** and add:
- `scoreivy-web`: `scoreivy.com` and `www.scoreivy.com`
- `scoreivy-admin`: `admin.scoreivy.com`
- `scoreivy-api`: `api.scoreivy.com`

Render shows the DNS record to create for each: a `CNAME` to `<service>.onrender.com` for subdomains, and an `A` (or `ALIAS`/`ANAME`) record for the bare `scoreivy.com`. Add those at the registrar. HTTPS certificates are issued automatically once DNS resolves, which can take from minutes to a few hours.

**Leave existing `MX` and email-related `TXT` records alone**, or email on the domain stops working. If the domain currently points at another website, replacing its `A`/`CNAME` records takes that site down.

### 5. Google sign-in

Google Cloud Console → **APIs & Services → Credentials** → your OAuth client → **Authorized JavaScript origins**, add:
`https://scoreivy.com`, `https://www.scoreivy.com`, `https://admin.scoreivy.com`

**OAuth consent screen**: set the app name, support email, and links to the privacy policy and terms, then **Publish app**. The site only asks for name and email, which normally doesn't need Google's review.

### 6. Stripe

1. Stripe dashboard → **Developers → Webhooks → Add endpoint**: `https://api.scoreivy.com/api/payments/webhook`, with events `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`, `charge.refunded`.
2. Copy the endpoint's signing secret into `STRIPE_WEBHOOK_SECRET` on `scoreivy-api`.
3. Buy a pack on the live site with test card `4242 4242 4242 4242` and check that the credits appear.
4. **Going live**: activate the Stripe account (business and bank details), repeat step 1 in live mode, and replace both Stripe values with the live ones.

While the test keys are in place nobody can actually pay, so the site can be checked in production safely.

### 7. Backups

Render's paid Postgres plans include daily backups and point-in-time recovery; check the plan's retention under the database's **Recovery** tab and try one restore before launch. Also download a question export (admin → Question Bank → Export CSV) now and then.

## Costs

Roughly: three small (`0.5c-512mb`) web services plus a small paid Postgres (`0.1c-256mb`), about $30–50/month to start. Check [Render pricing](https://render.com/pricing) for current numbers. Stripe charges per transaction.
